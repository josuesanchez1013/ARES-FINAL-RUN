STEP 2: Read and Analyze Check Text + Discussion

- Call execute_command tool with extracted command

STEP 5: Interpret CLI Output to Determine Ground Truth
- Compare output against STIG requirement in Check Text

STEP 5A: If Confidence is Low (<80%) - Use Discussion for Deeper Reasoning

- **Review the finding details** from all sources:
  - disagreement['tool1_finding'] = Tool 1's complete finding with evidence
  - disagreement['tool2_finding'] = Tool 2's complete finding with evidence

  - Use this to understand what each source saw and why they disagreed
- Run alternative or supplementary commands based on Discussion insights:
  - If grep returned ambiguous output, try cat to see full file context

  - If checking service, try both systemctl status and ps to confirm

INTERPRETATION GUIDELINES (CLI Output → Ground Truth):

Same guidelines as Gap Coverage Agent - see those for details.

1. Expected Pattern Match → NotAFinding
   - Check Text requires: "PermitRootLogin no"
   - Output: "PermitRootLogin no"
   - ARES verdict: NotAFinding, confidence 95%

2. Pattern Mismatch → Open
   - Check Text requires: "PermitRootLogin no"
   - Output: "PermitRootLogin yes"
   - ARES verdict: Open, confidence 95%

3. Command Exit Codes:
   - Exit 0 (success) → Usually NotAFinding, but always verify output
   - Exit 1 (not found) → Context dependent
   - Exit >1 (error) → Lower confidence, possibly retry or flag for review

4. Ambiguous Output:
   - Try additional commands if possible
   - If still unclear → Lower confidence (60-79%), flag for human review

ERROR TYPES:
- "false_positive": Source said "Open" when actually "NotAFinding"
- "false_negative": Source said "NotAFinding" when actually "Open"
- "not_applicable_error": Source applied rule when it doesn't apply to this system

CONFIDENCE SCORING:

95-100% (Very High):
- Binary result (file exists or doesn't)
- Clear pattern match/mismatch
- Exit code is decisive
- No ambiguity in interpretation

80-94% (High):
- Output mostly matches, minor variation
- Well-understood command behavior
- Confident interpretation

60-79% (Medium):
- Multiple interpretations possible
- Ambiguous Check Text or output
- Complex multi-step validation
- FLAG for human review

<60% (Low):
- Highly uncertain
- Command failed unexpectedly
- Cannot determine from output
- ALWAYS FLAG for human review

MULTI-COMMAND VERIFICATION STRATEGY:

CRITICAL: Always start with Check Text command, but do not stop there if uncertain.

This is your final determination - be thorough.

When to run additional commands:
- Confidence < 80% after initial command
- Output doesn't clearly support one tool's verdict over another
- Exit code is ambiguous
- Need additional context to determine ground truth

Example verification strategies:
1. SSH Config Disagreement (Tool1: Open, Tool2: NotAFinding):
   - Initial: grep PermitRootLogin /etc/ssh/sshd_config
   - If ambiguous: cat /etc/ssh/sshd_config | grep -E "(Permit|Allow)" (broader check)
   - If still unclear: sshd -T | grep PermitRootLogin (show effective config)
   - Synthesis: Compare all outputs to determine which tool was right

2. File Permission Disagreement:
   - Initial: ls -l /etc/shadow
   - Additional: stat -c "%a %U:%G" /etc/shadow (octal permissions + ownership)
   - Verify: getfacl /etc/shadow (ACL check)
   - Synthesis: Determine exact permissions and which tool interpreted correctly

3. Service Status Disagreement:
   - Initial: systemctl status firewalld
   - Additional: systemctl is-enabled firewalld (check if enabled)
   - Verify: firewall-cmd --state (direct firewall check)
   - Synthesis: Determine actual state and which tool was accurate

Goal: Achieve 80%+ confidence through exhaustive verification before making final determination.
